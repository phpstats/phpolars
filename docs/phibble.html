phibble and phplyr

Phibble\Polars\PolarsTable is a phibble table that keeps its data in a Polars DataFrame, so phplyr pipelines that start from it run in Polars. It belongs to phibble (since v0.2.0) and needs the php_polars extension. phibble only suggests the extension, so installing phibble does not install phpolars. phibble’s Backends page compares its table backends.

Choosing an API

Need Use
dplyr semantics: NA, naRm, and groups in sorted key order phplyr or phibble on a PolarsTable
One pipeline on phibble’s in-memory DataFrame, a SQL table, and Polars phplyr or phibble
Polars’ null semantics the phpolars API
Lazy scans, the streaming engine, sinks, or SQL over data frames the phpolars API
PHP closures in many methods phibble’s in-memory DataFrame. On a PolarsTable, each closure converts the table (see What runs in Polars).

A pipeline on a PolarsTable

  • PHP 8.5+
  • PHP 8.3–8.4
use Phibble\Polars\PolarsTable;
use function Phplyr\{col, filter, group_by, mean, n, summarize};

$table = PolarsTable::fromPolars(Phpolars\read_csv('sales.csv'));

$out = $table |>
    group_by('store') |>
    filter(col('units')->gt(mean('units', naRm: true))) |>
    summarize(orders: n(), avg_units: mean('units'));
use Phibble\Polars\PolarsTable;
use function Phplyr\{col, mean, n, phplyr};

$table = PolarsTable::fromPolars(Phpolars\read_csv('sales.csv'));

$out = phplyr($table)
    ->groupBy('store')
    ->filter(col('units')->gt(mean('units', naRm: true)))
    ->summarize(orders: n(), avg_units: mean('units'))
    ->get();

$out is a PolarsTable. $out->collect() copies it into a Phibble\DataFrame:

# A tibble: 4 × 3
  store orders avg_units
  <chr>  <int>     <dbl>
1 S1        32      9.72
2 S2        23      8.65
3 S3        22      9.36
4 S4        17      8.88

Moving data in and out

  • PolarsTable::fromPolars($df) wraps a phpolars DataFrame without copying it. A LazyFrame is collected first.
  • PolarsTable::fromTable($table) copies any phibble table into Polars and keeps types, groups, and factor levels. It throws when a list column would not round-trip exactly, for example when named arrays with different keys would become structs.
  • $table->polars() returns the underlying phpolars DataFrame.
  • $table->collect() copies the data into a Phibble\DataFrame.

Without the adapter, Phpolars\DataFrame::fromPhibble($table) reads any phibble table through toColumns(), and $df->toPhibble() returns a Phibble\DataFrame. toPhibble() needs phibble v0.2 or later.

What runs in Polars

Methods given column names or phibble expressions (Phibble\Expr, which phplyr’s helpers such as col(), mean(), and n() build) run in Polars with dplyr’s semantics:

  • NA propagates, and aggregates default to naRm: false.
  • Grouped mutate() and filter() evaluate aggregates and windows per group.
  • Groups follow sorted key order.
  • Joins follow dplyr 1.2, including join_by() inequality and rolling joins.
  • Pivots and most stringr and lubridate functions also run in Polars.

Some steps cannot run in Polars, and the adapter runs them on a phibble DataFrame and converts the result back:

  • a method given a PHP closure, because PHP code cannot run on Polars threads
  • any method on a rowwise table
  • grouped operations on factor keys that keep empty groups (phibble’s groupBy(drop: false) or phplyr’s group_by(_drop: false)), because Polars does not see empty groups
  • functions that the translator does not support, such as str_to_title()

PolarsTable::$fallbacks counts these conversions. Set PolarsTable::$strict = true to throw Phibble\Polars\PolarsFallback instead; its message names the method and the reason. Performance describes when a fallback costs time.

Missing values

phibble and phplyr treat PHP null as R’s NA, and a pipeline on a PolarsTable keeps those semantics. The phpolars API itself (DataFrame, LazyFrame, Expr, and Series) follows Polars, which treats null differently. Code moved from a phplyr pipeline to direct phpolars calls can return different results on the same data.

Operation phplyr, as in dplyr phpolars, as in Polars
sum, mean, min, max, std NA if any value is NA, unless naRm: true Nulls are skipped. col('x')->sum() over [1, null, 3] is 4.
Counting n() counts rows count() counts non-null values; len() counts rows
Comparison with null NA null. eqMissing() and neMissing() treat null as a value.
Arithmetic with null NA null
filter A row whose condition is NA is dropped A row whose condition is null is dropped
Sorting NA sorts last null sorts first; pass nullsLast: true
Join keys NA matches NA unless naMatches: 'never' null matches nothing unless nullsEqual: true
NaN is.na() is true for NaN NaN is a float value. isNull() is false for it; use isNan().

To get dplyr’s results from phpolars, compare nullCount() with zero before aggregating, sort with nullsLast: true, and join with nullsEqual: true.
